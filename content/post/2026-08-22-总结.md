## tokio::io::{AsyncReadExt, AsyncWriteExt}

- 扩展的异步读写方法

### 提供的方法

- .read()：从异步流中读取一些字节到 `buf`，返回实际读到的字节数。这个方法**不保证一次读满缓冲区**，可能只读一部分；返回 `0` 表示对端关闭/到达 EOF。
- .write()：向异步流写入一些字节，返回实际写入的字节数。同样**不保证一次写完整个缓冲区**，可能出现短写。
- write()和read()是单次操作
- .read_to_end()：一直读到 EOF，把所有读到的字节追加进 `buf`，返回总共读到的字节数。适合读完整文件或完整响应体。
- .write_all()：把 `buf` 里的内容**全部写完**，内部会循环调用 `write` 直到写满，或者遇到错误。适合一次性发送完整数据。
  这几个方法都是从 `AsyncReadExt` / `AsyncWriteExt` 导入后，才能在 `TcpStream`、`File`、`DuplexStream` 等类型上调用的。

## pub async fn read_frame(stream: &mut TcpStream) -> std::io::Result<(u64, Vec<u8>)>

```
pub async fn read_frame(stream: &mut TcpStream) -> std::io::Result<(u64, Vec<u8>)> {
    let mut head = [0u8; HEAD_LENGTH];
    stream.read_exact(&mut head).await?;

    let msg_id = u64::from_be_bytes(head[0..8].try_into().unwrap());
    let msg_len = u32::from_be_bytes(head[8..12].try_into().unwrap()) as usize;

    if msg_len > MAX_LENGTH || msg_len == 0 {
        return Err(std::io::Error::new(
            std::io::ErrorKind::InvalidData,
            format!("非法消息长度: {}", msg_len),
        ));
    }

    let mut body = vec![0u8; msg_len];
    stream.read_exact(&mut body).await?;

    Ok((msg_id, body))
}
```

### pub async fn read_frame(stream: &mut TcpStream) -> std::io::Result<(u64, Vec<u8>)>

- pub：公开函数
- assync fn ：异步函数，调用要`await`，返回的是`Future`
- `stream: &mut TcpStream`：参数是一个对 `TcpStream` 的可变引用。异步操作可能需要读取并推进流内部状态，所以需要 `&mut`。
- `-> std::io::Result<...>`：返回 `Result`，错误类型是 `std::io::Error`，用 `?` 可以直接向上传播 I/O 错误
- `(u64, Vec<u8>)`返回的元组
- 元组的中的u64是督导的有效数据
- Vec<u8>读到的数据内容

### let mut head = [0u8; HEAD_LENGTH];

- 就是HEAD_LENGTH去用0填充，初始化的消息的头数组

### stream.read_exact(&mut head).await?;

- `stream`一个异步流，用来获取数据的
- `read_exact`：`AsyncReadExt`的trait的扩展方法，保证`head.len()`读满才返回，就是asio库的async_read()
- &mut head：将head定义为缓冲区
- `await`等待异步曹组哦完成
- `?`发生I/O错误，立刻返回`Err(...)`，如果中途遇到EOF（对端关闭）导致读不满会返回

### let msg_id = u64::from_be_bytes(head[0..HEAD_ID_LENGTH].try_into().unwrap());

- 取得缓冲区的前8字节即ID

### let msg_len = u32::from_be_bytes(head[0..HEAD_LEN_LENGTH].try_into().unwrap()) as usize;

- 取得缓冲区的前8-12字节即消息长度
- try_into()把获得的切片转成`[u8;8]`的样式，再用`u64::from_be_bytes` 按大端序解释成 `u64`

### if msg_len > MAX_LENGTH || msg_len == 0

- 判断消息合法性
- 不合法返回（消息长度非法）

```rust
if msg_len > MAX_LENGTH || msg_len == 0 {
return Err(std::io::Error::new(
std::io::ErrorKind::InvalidData,
format!("消息长度非法，{}", msg_len),
));
}
```

## pub async fn write_frame(stream:&mut TcpStream,msg_id:u64,body:&[u8])->std::io::Result

```rust
pub async fn write_frame(stream: &mut TcpStream, msg_id: u64, body: &[u8]) -> std::io::Result<()> {

    let mut buf = Vec::with_capacity(HEAD_LENGTH + body.len());

    buf.extend_from_slice(&msg_id.to_be_bytes());
    buf.extend_from_slice(&(body.len() as u32).to_be_bytes());
    buf.extend_from_slice(body);

    stream.write_all(&buf).await
}
```

- 把一帧的数据写进通讯里
- Vec::with_capacity`，返回的是 `Vec<u8>`即缓存的数据
- `msg_id.to_be_bytes()` 把 `u64` 转成 8 字节大端序，`extend_from_slice` 放进 `buf`；
- `extend_from_slice`会直接追加到末尾，也可以使用g`unsafe`要自己保证内存安全。
- `body.len() as u32` 把长度压成 4 字节，同样按大端序写入；
- 再把真正的 `body` 追加进去；
- `stream.write_all(&buf).await` 一次性把整个帧写到 TCP 流中，`await` 等异步写入完成。
- 返回值是 `std::io::Result<()>`：成功返回 `Ok(())`，失败返回 `Err(std::io::Error)`。内部 `stream.write_all(&buf).await` 的返回值正是 `Result<()>
