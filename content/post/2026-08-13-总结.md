# rust

## 错误处理

- 编译时提示错误，并提示你处理
- 错误分类：可恢复：文件未找到之类的；不可恢复：bug
- 没有异常机制
- 可恢复：Result<T,E>
- 不可恢复：panic!宏

### panic!

- 程序会立即停止执行

#### 宏执行时

- 打印错误
- 栈展开，清理
- 退出程序

#### 操作

- 栈展开
- 中止栈：不进行清理，直接停，OS进行清理,适合减小二进制文件的情况

#### result枚举

- T成功：OK变体类型
- E失败：Err变体类型

#### match

- 通过match枚举类型处理

#### 闭包的实现

- unwrap_or_else()处理

#### 传播错误

- 将错误返回给调用者
- 用return返回给调用
- ?运算符进行传播错误
- 方式from函数时会被转换成当前函数返回类型所定义的错误类型
- main的返回类型可以是result类型

#### 什么时候用

- 定义一个可能会失败时，优先用return
- 编写原型代码
- 演示代码时
- 测试代码
- 指导性错误

# C++

## std::chrono::steady_clock

这是 `std::chrono::steady_clock` 的一个**时间点类型**，用于保存单调时钟的某个时刻。`LastUsedTime;` 只是声明了一个该类型的变量，默认构造函数会把它初始化为时钟的“纪元”（epoch），也就是该时钟的起点。对 `steady_clock` 来说，纪元通常不是“当前时间”，而是系统启动后的某个基准时刻。

```cpp
#include <chrono>
#include <iostream>
int main() {
std::chrono::steady_clock::time_point LastUsedTime; // epoch，不是当前时间
// 正确初始化成“当前时刻”：
LastUsedTime = std::chrono::steady_clock::now();
// 测量时间间隔：
auto start = std::chrono::steady_clock::now();
// ... 做点什么 ...
auto end = std::chrono::steady_clock::now();
auto elapsed = end - start;
std::cout << "elapsed: " << std::chrono::duration_cast<std::chrono::milliseconds>(elapsed).count() << " ms\n";
}
```

注意：

- `steady_clock` 是单调递增的，适合做耗时统计，不适合转成“日历时间”。
- 默认构造的 `time_point` 一般不要理解为“无效/未设置”。想表达“从未用过”，用 `std::optional<std::chrono::steady_clock::time_point>` 或额外 `bool` 标志更清晰。

## mysql_options(conn, MYSQL_OPT_CONNECT_TIMEOUT, &TimeOut);

这是 MySQL C API 中用来设置连接超时时间的函数调用。`MYSQL_OPT_CONNECT_TIMEOUT` 表示设置连接阶段的超时秒数，`&TimeOut` 指向一个 `unsigned int` 变量（未来版本中可能是 `unsigned int`），存放你想要等待的秒数。必须在 `mysql_real_connect()` 之前调用才有效。

```c
#include <mysql.h>
#include <iostream>
int main() {
MYSQL* conn = mysql_init(nullptr);
if (!conn) return 1;
unsigned int TimeOut = 5; // 5秒
mysql_options(conn, MYSQL_OPT_CONNECT_TIMEOUT, &TimeOut);
if (!mysql_real_connect(conn, "localhost", "user", "pass", "db", 3306, nullptr, 0)) {
std::cerr << mysql_error(conn) << '\n';
}
mysql_close(conn);
return 0;
}
```

注意：`mysql_options()` 返回 `int`，成功返回 0，失败返回非 0。实际可用超时还受操作系统和网络环境影响，这个设置并非绝对精确。

# unity

## 反射机制

- 开发本质，利用反射和引擎的提供的各种功能进行拓展开发
- 反射是指程序在运行时能够检查自身结构、获取类型信息并动态调用成员的能力。常见于 C#/Java/Python 等语言：运行时能拿到一个对象的类型、方法、属性，甚至动态创建实例、调用方法，而不需要编译期写死。

### GameObject

- 所有对象的基类类型
- 通过关联脚本去实现其他功能
- 一定关联transform
- C#脚本去关联此对像实现

#### 脚本

- 在project下选择文件夹创建
- 直接拖动关联脚本
